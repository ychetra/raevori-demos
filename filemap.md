# File map

- `app/` — Next.js routes (pages and API)
- `app/layout.tsx` — root layout, fonts (Geist, Noto Sans Khmer), metadata
- `app/globals.css` — brand tokens (copied from raevori-web) and global styles
- `app/page.tsx` — home page: headline + five demo cards (1 column; 2 columns from md with Booking full width; from lg 2 + 3 on a 6-column grid) (previews drawn in markup), canonical `/`
- `app/robots.ts`, `app/sitemap.ts` — robots.txt (disallow /api/, /dev/) and sitemap (/, /table-order, /shop-assistant, /shop-pulse, /queue, /booking); `app/opengraph-image.tsx` — 1200×630 social image
- `app/api/health/route.ts` — health check for Coolify/Docker (`ok`)
- `features/table-order/types.ts` — Order (new/preparing/ready/done/cancelled), MenuItem (soldOut/hidden), ShopSettings, CartLine, RoomEvent types; `menu.ts` — MENU (14 items) + option groups, copyMenu(), optionsFor(), DEFAULT_ART; `km.ts` — all Table Order strings EN/KM
- `features/table-order/format.ts` — optionSummary(), ageLabel(); `api.ts` — client fetch helpers; `useRoom.ts` — live orders, menu and settings hook (SSE + reconnect + closed; default MENU/settings while connecting)
- `features/table-order/ui/` — Kitchen (laptop board + QR), CustomerApp (phone flow), ItemSheet, MenuArt (SVG illustrations)
- `app/table-order/page.tsx` — kitchen page; `app/table-order/menu/page.tsx` — phone menu (noindex)
- `features/table-order/server.ts` — the process-wide store singleton, room-creation limiter (40 per IP per rolling hour, shared by Table Order and Shop Pulse) + error→HTTP mapping
- `app/api/rooms/**` — room API: create (returns the admin PIN), snapshot (orders, menu, settings), post order (sold_out/closed/price_changed), advance order, SSE events
- `app/api/rooms/[id]/admin/**` — café owner admin API (signed room cookie): login (POST PIN, GET session check), menu (PUT edit, POST add), orders/[orderId] (PATCH done/cancelled), settings (PUT), export.csv (GET), reset (POST)
- `features/table-order/pricing.ts` — priceOrder(lines, menu = MENU): server-side prices from the room's menu; `store.ts` — in-memory RoomStore (rooms with their own menu, settings and PIN; orders, done/cancel, admin edits, PIN tries, live subscribers, expiry)
- `features/table-order/admin.ts` — admin rules: item/settings/reason validation, DEFAULT_SETTINGS, isOpen() (Phnom Penh hours), ordersCsv(); `admin-auth.ts` — the signed `ra_admin` cookie (per room, 2 h); `admin-api.ts` — client fetch helpers for the admin API
- `lib/signed-cookie.ts` — HMAC sign/verify (with a purpose), readCookie(), isSecure(); used by the chat session, the café admin and the queue admin
- `features/shop-assistant/` — Shop Assistant catalog, tools, chat engine, screens (Tasks 8-11)
- `features/shop-assistant/km.ts` — all Shop Assistant strings EN/KM (products, colours, zones); `catalog.ts` — CATALOG (20 products, stock), COLORS, ZONES
- `features/shop-assistant/tools.ts` — searchProducts/checkStock/quoteDelivery/createOrder (Khmer-aware matching); `limits.ts` — per-session/IP chat limits, per-IP and global model-call budgets (Phnom Penh days)
- `features/shop-assistant/model.ts` — ChatModel interface + chat types; `agent.ts` — runTurn() tool loop, cleanHistory(), executeTool(); `gemini.ts` — Gemini adapter, system prompt, tool declarations; `fake-model.ts` — scripted model (CHAT_MODEL=fake); `replay.ts` — the sample chat; `session.ts` — signed ra_s cookie; `server.ts` — limiter singleton + createModel()
- `app/api/chat/route.ts` — POST chat turn (limits → runTurn → text + cards)
- `features/shop-assistant/api.ts` — client sendChat(); `ui/` — ShopAssistant (page layout + how-it-works), Chat (messages, suggestions, busy card, replay, KHQR sheet), Cards (product/delivery/order), ProductArt (SVG clothes)
- `app/shop-assistant/page.tsx` — Shop Assistant page
- `features/shop-pulse/` — Shop Pulse: `types.ts` (Sale, fromOrder, liveSales without cancelled orders), `time.ts` (Phnom Penh day/hour helpers), `history.ts` (28 days of deterministic sales), `metrics.ts` (kpis, byHour, byDay, topItems, paymentSplit, dailyReport), `km.ts` (all Shop Pulse strings EN/KM)
- `features/shop-pulse/ui/` — ShopPulse (page body: intro, live dashboard, room + clock wiring), ColumnChart (SVG column chart with step line, tooltip, keyboard, sr-only table), format.ts (Phnom Penh time/date labels, % and change labels)
- `app/shop-pulse/page.tsx` — Shop Pulse page (noindex with `?room=`)
- `features/queue/` — Smart Queue: `types.ts` (Ticket, QueueEvent incl. config events, Queue with services/counters/settings/PIN, ServiceConfig, CounterConfig, QueueSettings, QueueStats), `store.ts` (in-memory QueueStore: seeded rooms with their own config and PIN, take/call/recall/leave with hidden-service and closed-counter refusals, auto-call top-up with walk-ins from visible services, admin edits, reset, PIN tries; position(), estimateWait() (sum of service minutes ahead), waitMinutes()), `server.ts` (store singleton, creation limiter, validation, error→HTTP, publicQueue(), guardAdmin()), `api.ts` (client fetch helpers), `useQueue.ts` (live tickets and config hook; default config while connecting), `km.ts` (all Smart Queue strings EN/KM)
- `features/queue/admin.ts` — queue admin rules: service/counter/settings validation, defaultConfig(), serviceName(), queueStats() (today, Phnom Penh), ticketsCsv(); `admin-auth.ts` — the signed `rq_admin` cookie (per queue, 2 h); `admin-api.ts` — client fetch helpers for the queue admin API
- `app/api/queues/**` — queue API: create (returns the admin PIN), snapshot (tickets + config), take a ticket (bad_service/hidden), call (counter_closed), recall, leave, SSE events (snapshot, ticket, config)
- `app/api/queues/[id]/admin/**` — queue owner admin API (signed queue cookie): login (POST PIN, GET session check), services (PUT edit, POST add), counters (PUT), settings (PUT), stats (GET), export.csv (GET), reset (POST)
- `features/queue/ui/` — Board (laptop page: intro + QR card + steps, dark waiting-room board, staff bar with call/recall/auto-call, call highlight, 429 message), TicketApp (phone: pick a service, live ticket with position/wait/progress, "It's your turn" overlay, leave with confirm, done/left/closed screens; ticket remembered in sessionStorage per room)
- `app/queue/page.tsx` — Smart Queue board page (noindex with `?room=`); `app/queue/ticket/page.tsx` — phone ticket page (noindex)
- `features/booking/` — Booking with a deposit (salon): `types.ts` (Booking, HoldInput, BookingEvent), `salon.ts` (opening hours, SERVICES with minutes and $ prices, STYLISTS roster, DEPOSIT $3, HOLD_MS), `availability.ts` (pure availability(), isFree(), freeStylist() for "Anyone", blocks()), `store.ts` (in-memory BookingStore: seeded rooms, hold/pay/setStatus, lazy hold expiry, sweep), `server.ts` (store singleton, creation limiter, validation, error→HTTP), `api.ts` (client fetch helpers, CreateBookingError), `useBooking.ts` (live bookings hook), `km.ts` (all Booking strings EN/KM, incl. weekdays/months); Phnom Penh time helpers come from `features/shop-pulse/time.ts`
- `features/booking/ui/` — Calendar (laptop page: intro + QR card + steps, dark salon calendar with 7-day switcher, 3 stylist columns 09:00-19:00, booked/arrived/no-show/striped held blocks, current-time line, Arrived/No-show popover, new-booking highlight, 429 message; scrolls sideways inside the card on phones), BookApp (phone: service → stylist/Anyone → day + live free times → name/phone → KHQR deposit with hold countdown → confirmation with .ics; taken/expired/closed; hold remembered in sessionStorage per room), format.ts (fill() placeholders, day labels, mmss, shown(), bookingIcs())
- `app/booking/page.tsx` — Booking calendar page (noindex with `?room=`, OG title/description); `app/booking/book/page.tsx` — phone booking page (noindex)
- `app/api/bookings/**` — booking API: create, snapshot, hold a slot, pay a hold, staff status, SSE events (also sweeps the room's run-out holds every 5 s)
- `lib/i18n.ts` — Lang/Text types and pick(); `lib/money.ts` — usd(), khr() at 4,100; `lib/client-ip.ts` — clientIp() (cf-connecting-ip, then first X-Forwarded-For hop), used by the chat and rooms APIs
- `components/shared/` — DemoBar, LangToggle, PhoneFrame, Qr (+ qr-svg helpers), KhqrCard, khqr.ts (demo QR value), km.ts (shared Khmer)
- `app/dev/ui/` — noindex gallery of shared components for review
- `scripts/shot.mjs` — screenshot a URL at a width for design review
- `tests/unit/` — Vitest tests (`npm test`)
- `tests/e2e/` — Playwright tests (`npm run e2e`; builds and runs the standalone server on :3012); `home.spec.ts` covers home links, robots/sitemap/OG, `?room=` noindex and a keyboard-only Table Order run; `table-order.spec.ts` drives a laptop + phone together; `shop-assistant.spec.ts` runs against CHAT_MODEL=fake
- `scripts/start-standalone.mjs` — runs the production build like the Docker image does
- `Dockerfile` — production image for Coolify (Node standalone server on :3000)
- `docs/SPEC.md` — approved design; `docs/PLAN.md` — task list and status
- `CLAUDE.md` — rules for any session working here
